做一次**只读**的四方对齐审查，不要改任何代码。逐项输出「一致 ✅ / 不一致 ❌ + 具体位置」。

## 检查项

1. **DDL 对齐**：`desktop/db/schema.sql` 与 `docs/02-数据模型.md` 的 SQL 是否逐字一致（表数、字段、类型、约束、索引、CHECK、注释里的级联策略）。
2. **迁移对齐**：`db/migrations/` 顺序执行到最新版本的结果，是否等价于 `schema.sql`；`schema_meta.version` 是否为迁移文件最大编号。
3. **API 对齐**：`docs/03-API接口规范.md` 列出的 34 个接口，逐个在 `desktop/api/` 中找到实现；核对方法、路径、请求字段必填性、响应字段全集、错误码与 HTTP 状态码。
4. **枚举与类型对齐**：全项目 grep 是否出现小写 `IN`/`OUT` 之外的枚举变体（`STOCK_IN`/`import`/`io_type`）、是否有 `true/false` 文本存进布尔列、是否有 `datetime.now()` 裸调用 / `utcnow` / `CURRENT_TIMESTAMP`。
5. **响应包络对齐**：是否所有出口都经 `core/response.py`；`code!=0` 是否都配非 2xx；可空字段是否返回 `null` 而非省略键。
6. **PRD 偏差**：`docs/01-产品需求文档.md` 里被本阶段实现推翻或尚未实现的条目（尤其 5.x 各模块的「异常处理」表是否都有对应代码分支）。

## 禁止

- 不要引入新依赖、不要改 schema、不要"顺手修复"任何不一致。
- 不确定是否算不一致的，标 ⚠️ 并说明两种解读，交给我判断。

## 输出

按上面 6 组分组，每组给 ✅/❌ 清单 + 文件与行号 + 一句话修复建议（建议不执行）。最后给一段「本次必须修的 3 个最高优先级不一致」。
