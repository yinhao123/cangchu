# 07 · 运维手册（电脑端）

> 面向「装好了之后要维护它的人」。全部操作都有页面入口，只有两处需要命令行（重算、检查）。

## 1. 六个必须会做的操作

### 1.1 按 trace_id 查一次操作发生了什么
每个页面右上角/每次操作 Toast 会带 8 位 `trace_id`，报错时也带。
```
1) 打开 %LOCALAPPDATA%\ScanableSelf\logs\app.log（每行一个 JSON）
2) 搜 trace_id 值，同一请求的所有行都用它串联（含 SQL 失败、事务回滚、外部耗时）
3) 时间线对不上了再按 username + action + 时间段捞
```
关键 action 名：`auth.login` / `auth.login_failed` / `stock.in` / `stock.out` / `stock.adjust` /
`stock.reverse` / `sync.batch` / `backup.create` / `backup.restore` / `settings.update`

### 1.2 备份（RPO ≤ 24 小时）
- 自动：每天 03:00（需程序在跑）→ 文件在 `%LOCALAPPDATA%\ScanableSelf\backups\inventory_YYYYMMDD_HHMMSS.db`。
- 手动：`/backup` 页〔立即备份〕。**每次要做危险操作前手动备份一次**。
- 保留：最近 7 份 + 每月首份留 12 个月。
- ⚠️ **备份含全部业务数据，与主库同等保护**：不要放到共享盘或网盘公共目录。
- ⚠️ 不要把「拷一份 .db」当备份：WAL 模式下未落盘数据在 `-wal` 文件里，只拷主文件会得到残缺库（系统内部用在线一致性快照，见 T-04）。
- **备份必须做过一次真实恢复才算有效**（见 1.3）。

### 1.3 恢复到指定时间点（RTO ≤ 30 分钟）
```
1) /backup 页选文件 → 输入当前账号密码（二次确认）
2) 系统自动先把当前库另存为 pre_restore_*.db（万一要回退）
3) 恢复 → 校验（integrity_check + 关键表行数）→ 按提示重启程序
4) 重启后核对：当日流水笔数、库存总数是否与预期一致
```
命令行等价：停程序 → 把备份文件复制为 `inventory.db`（此时 WAL 已随干净关闭合并）→ 启动。
**若不确定程序是否干净关闭过，一律用页面恢复入口，不要手工复制。**

### 1.4 库存对不上（最常见故障）
```
第 1 步  体检：python manage.py check        → 看「流水聚合 vs stock_current」是否一致
第 2 步  重算：python manage.py recalc-stock --dry-run   → 输出逐行 diff（不改数据）
第 3 步  判断差异性质：
        · 单笔错录 → 用〔单据撤销〕红字冲销（保留痕迹，禁止删流水）
        · 实物与账面不符 → 用〔库存调整 ADJUST〕，备注必须写清原因（admin 权限）
        · 系统性偏差（diff 大面积） → 才执行 recalc-stock --apply（会先自动备份）
第 4 步  复盘：查 diff 记录的 product_id + 时间 → 到流水里找是哪笔操作造成的
```
**禁止**：手工 `UPDATE stock_current`（下一次重算会覆盖你的手工修正，且掩盖真实原因）。
**禁止**：删除 `stock_logs` 里的行 —— 它是账本，只能冲销。

### 1.5 手机连不上电脑（四步排查）
| 步 | 检查 | 处置 |
|---|---|---|
| 1 | 电脑 `/connect` 页广播状态是否「正常」 | 黄条「自动发现不可用」= Windows 防火墙拦了 UDP（首次运行点了取消）→ 允许 ScanableSelf 通过专用网络，或改用扫码配对 |
| 2 | 手机与电脑是否**同一 WiFi、同一网段** | 路由器开了 **AP 隔离** → 手机能上外网但打不开 `http://<电脑IP>:5000`，只能在路由器关闭隔离，或让手机连电脑热点 |
| 3 | 端口是否被自动改过 | 电脑装了别的软件占 5000 → 程序会自动换 5001~5010，`/connect` 页与二维码会显示实际端口，手机需重新扫码 |
| 4 | 电脑 IP 是否变了 | 路由器重新分配过地址 → 关掉手机 APP 重开（会重新自动发现）；长期方案：路由器给电脑绑定静态 IP |
兜底顺序：自动发现 → 扫配对二维码 → 手机设置页手输 `IP:端口`。

### 1.6 换电脑迁移
```
旧电脑：停程序（让 WAL 合并落盘）→ 备份一次（保险）
        → 拷贝整个 %LOCALAPPDATA%\ScanableSelf\ 目录到新电脑同一路径
新电脑：装 ScanableSelf.exe → 启动（会自动建库并检测到已有数据，跳过种子）→ 核对数据 → 删除旧电脑数据目录
注意：数据库/日志/备份都在那个目录里，exe 本身无状态，可任意升级覆盖。
     不要把程序与数据放在网络盘（SMB/NAS）上运行：WAL 在网络盘不可靠，会随机报错甚至损坏数据。
```

### 1.7 开机自启
- 命令行：`python manage.py autostart on|off|status`（写入/删除「启动」文件夹里的 `.cmd`）。
- 等价手工做法：把启动 `.cmd` 放进「启动」文件夹，或用任务计划程序配「用户登录时」启动。
- 自启的判据：重启机器后，`docs/07` 里的访问地址能打开登录页；界面「手机配对」页也能看到自启状态。

### 1.8 现场同事报「打不开界面」时的三步

```
第 0 步 服务端在跑吗：在同一台机器浏览器打开 http://127.0.0.1:5000/ —— 能开说明服务正常，问题在网络
第 1 步 地址对吗：看 %LOCALAPPDATA%\ScanableSelf\ 下的访问地址文件（端口可能是 5001~5010）
第 2 步 防火墙放行了吗：按「手机配对」页给出的 netsh 命令放行 TCP 5000~5010 与 UDP 55555
```
> 端口为什么不是 5000：5000 被别的软件占用时程序会自动顺延到 5001~5010，
> **以启动信息里显示的端口为准**（广播报文与配对二维码里的端口也会同步更新）。

### 1.9 演示数据（给客户演示 / 培训用）
```
方式 A（推荐，交付包自带）：双击 exe 同目录的「启动演示模式.bat」
  → 数据目录自动切到 <解压目录>\demo-data（与真实账本物理隔离）
  → 首次启动自动灌演示数据（幂等：第二次启动直接跳过）
  → 3 秒后自动打开浏览器

方式 B（开发机 / 命令行）：
  python manage.py initdb        # 新库才有意义
  python manage.py demo-data     # 灌演示数据；已有流水时会拒绝，加 --force 才强制执行
  python manage.py check         # 必须输出「自检通过」

重建演示环境：停程序 → 删掉 demo-data 目录（或开发机换一个 SCANABLE_DATA_DIR）→ 重新执行
演示账号：wh01 / Demo2026（环境变量 SCANABLE_DEMO_PASSWORD 可改）；admin 初始口令仍是 admin123
```
> 演示数据全部经 services 层写入（出入库 → 采购/领用/调拨单据 → 审批过账），
> 因此库存与流水一定自洽；它**不会**绕过幂等、快照、原子扣减，也不会直接改 `stock_current`。

## 2. 故障处理对照

| 现象 | 大概率原因 | 处置 |
|---|---|---|
| 双击 exe 没反应 | 启动异常但无控制台看不见 | 用调试版 `ScanableSelf-debug.exe` 看报错；或查 `logs/crash.log`（T-17） |
| 浏览器打开**一片白** | 前端构建产物没随包（`static/spa` 缺失） | 页面会显示「前端资源缺失」的人话提示：开发机 `cd desktop/web && npm run build`；打包机检查 `.spec` 的 `datas`（T-36） |
| 打开后只有文字没有样式 | 客户端内核太旧（antd v5 需要 Chrome 88+） | 实测浏览器内核版本；按 docs/04 T-37 处置或改用 Chrome/Edge 109 |
| 界面卡在登录页反复跳 | Token 失效或浏览器禁用了 sessionStorage | 重新登录；确认浏览器未禁用站点数据 |
| 报 `TemplateNotFound` | 打包未带模板（现在只剩错误页） | 检查 `.spec` 的 `datas`，重打包（T-16） |
| 条码打印是空白 | PyInstaller 未带 barcode 字体 | 补 `datas` 里字体路径，重打包 |
| 标签打印预览里出现搜索框/表格 | 浏览器按「整页」打印 | 用页面上的「打印」按钮（走 `@media print`），不要用浏览器另存的整页 |
| 某个接口一直提示 404 | 路径写错 | 该现象**不会**被前端兜底换掉：`/api/*` 的 404 仍是 JSON（T-35）。对着 docs/03 核路径 |
| 启动报「数据库可能损坏」 | 非正常关机 / 磁盘问题 | 进只读模式，按 1.3 从备份恢复（L4 降级） |
| 频繁 `database is locked` | 长事务、程序放在网络盘，或同时写入的客户端过多 | 查日志定位持事务操作；确认程序与数据在本地磁盘；把同时写入的浏览器客户端控制在 3~5 个以内 |
| 仪表盘「备份已停止」红条 | 自动备份连续失败 3 次 | 查磁盘空间/目录权限 → 立即手动备份 |
| Excel 打开 CSV 中文乱码 | 旧版导出未带 BOM | 确认 `utf-8-sig`（T-10），重新导出 |
| 库存出现负数 | 有代码绕过了原子扣减 | 立即排查（违反 T-06）；跑 recalc 对账，查最近流水定位操作 |
| Win7 上装不上 Python / exe 起不来 | 版本线不对 | 必须是 Python 3.8.10 + PyInstaller 5.13.2；依据与真机清单见 docs/12 |
| 演示模式启动后还是旧内容 | `demo-data` 目录里已有旧数据（演示数据按版本只灌一次） | 停程序 → 删 `demo-data` → 重新双击「启动演示模式.bat」 |
| `demo-data` 提示「已有业务流水，未灌演示数据」 | 演示目录被当真实库用过（手工出过库） | 换一个目录（`SCANABLE_DATA_DIR`）或删库重建；不要在原库上强行 `--force` 混数据 |

## 3. 性能基线（发版后实测填写，用于日后对比发现退化）

| 接口 | P50 | P95 | 实测值（Day3 填写） |
|---|---|---|---|
| `/api/ping` | 3ms | 10ms | ⬜ |
| `/api/products/by-barcode/<bc>` | 8ms | 20ms | ⬜ |
| `/api/stock/in` | 30ms | 150ms | ⬜ |
| `/api/sync/stock-logs`（200 条） | 120ms | 400ms | ⬜ |
| exe 冷启动到服务可用 | ≤3s | ≤8s | ⬜ |

数据量增长到 5 万条流水时重新测量一次；若 P95 超基线 2 倍 → 查索引与慢查询（`manage.py check`）。

## 4. 定期维护（每月一次，5 分钟）
```
[ ] 磁盘剩余空间 > 5 GB
[ ] 做一次手动备份，并按 1.3 演练恢复一次（很多人备份了却从没试过恢复）
[ ] 检查 logs/ 大小（轮转上限 10MB×10，异常膨胀说明有循环报错）
[ ] pip-audit 扫依赖漏洞（高危 24h 内评估、72h 内更新）
[ ] 手机设备列表核对：/users 页吊销不再使用的设备 Token
```
