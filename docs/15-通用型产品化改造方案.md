# 15 · 通用型产品化改造方案（淘宝销售版）

> 本文回答一个问题：**作为在淘宝销售的通用型仓库管理软件，距离「客户自己买回去就能用、不退货、不差评」还差什么。**
>
> 只做设计与计划，不直接改代码。所有 DDL / 接口 / 文件落位必须先过 `docs/02`、`docs/03`、`docs/04`，再动实现。
>
> ★ **与 `docs/14` 的分工**：`docs/14` 解决「交付给一家具体客户还缺什么」（导入、盘点、打印、销货、成本）；
> 本文解决「作为标准化商品卖给不特定客户还缺什么」（开箱可用、承诺兑现、档案通用、售后可控）。
> 重叠处只写差异，已排期项直接引用 `docs/14`，不重复排期。
>
> ★ 估时为**含测试与前端**的人日，口径同 `docs/14`。
>
> ★ 结论来源：`docs/10` 实际完成度、`docs/14` 已排期项、`db/schema.sql`、`desktop/` 代码实查、
> 以及淘宝同类商品（几十元单机版 ~ 几百元年费版）的公开功能与差评分布。

## 1. 定位与边界

### 1.1 三条生死线

| 生死线 | 含义 | 违反后果 |
|---|---|---|
| **开箱可用** | 不实施、不培训、不配环境，双击就见到界面 | 退款，客服无法挽回 |
| **承诺兑现** | 详情页/主图写的能力必须真的存在 | 淘宝"描述不符"，退货 + 差评 + 平台介入 |
| **数据不丢** | 客户没有 IT，重装/换机/断电都不能丢账 | 纠纷、差评，致命口碑 |

### 1.2 卖给谁 / 不卖给谁（直接决定退货率）

**建议主打 3 类场景**（功能覆盖最好、话术最好讲）：

1. 小型工厂/加工厂的**备件与原料台账**（领用、借用、退库、盘点）
2. 五金/汽配/日用百货**批发档口**（多仓调拨、按客户出库、对账）
3. 淘宝/拼多多**卖家自有小仓**（只做本地库存台账，不接平台订单）

**明确不适用**（写进详情页"不适用场景"，比事后解释便宜十倍）：

- 食品/医药/化妆品等**需要批次或保质期追溯**的
- 按**重量/长度/体积**计量（kg、米、升）且必须小数的
- 需要**货架库位到具体层位**、波次拣货的
- 需要**对接淘宝/拼多多订单自动打单、快递面单**的
- 需要**多公司账套、应收应付、发票**的
- 需要**异地/外网访问**的（本产品是局域网单机）

### 1.3 与 docs/14 的已完成项对照（不重复排期）

## 2. B0 · 能卖（P0，7.5 人日）

### TP-01 双击 exe 没有任何界面反馈

| 项 | 内容 |
|---|---|
| **现状** | 纯服务端形态：启动只写状态文件与日志，不弹窗。`desktop/` 全量搜索无 `webbrowser`、无托盘、无开机自启。 |
| **风险** | 买家判断标准是"双击后有没有界面"。没反应即申请退款。 |
| **改法** | ① 启动成功后 `webbrowser.open("http://127.0.0.1:<实际端口>/")`，端口必须取自动换端口后的实际值；② 托盘图标（`pystray`），菜单含「打开界面 / 复制局域网地址 / 查看日志 / 退出」；③ 设置项 `autostart` 写 `HKCU\...\Run`（不需管理员）；④ 端口全被占用时托盘气泡提示。 |
| **依赖** | 新增 `pystray==0.19.5`（Py3.8 兼容）。**必须先改 `docs/01` 2.1 版本表再安装**；PyInstaller 补 `hiddenimports` 与图标资源。 |
| **退路** | 仅自动开浏览器 + 桌面生成 `打开管理界面.url`；缺点是无法优雅退出，不推荐。 |
| **验收** | 干净 Win7 双击 → 3 秒内浏览器自动打开登录页；托盘可见；退出后进程消失；勾选自启后重启自动运行。 |
| **估时** | 2.5d（含打包联调） |

### TP-02 Win7 默认浏览器是 IE11，SPA 跑不起来

| 项 | 内容 |
|---|---|
| **现状** | 前端为 React 18 + antd 5，IE 下必然白屏；Win7 默认浏览器即 IE。 |
| **风险** | **白屏是最高频退款理由**，且客户不会想到"换浏览器"。 |
| **改法** | ① 服务端在 SPA 回退处判 UA（`MSIE` / `Trident` / 360 兼容模式），**直接返回自包含静态页** `static/unsupported-browser.html`（纯 HTML+CSS，不引外部资源），提示改用 Chrome / Edge / 360 极速模式，并给出托盘里可复制的正确地址；② 安装包内附便携版浏览器（Win7 最后可用为 109），托盘菜单「用自带浏览器打开」拉起，绕开默认浏览器；③ 详情页图示"360 要切极速模式"。 |
| **注意** | 静态页放 `static/` 由现有静态服务提供，**不得新增服务端渲染页面**（红线 8）。UA 判断只做拦截+引导，不做浏览器适配。 |
| **验收** | IE11 UA 请求 `/` → 返回引导页（非白屏）；Chrome 正常进 SPA；托盘可拉起自带浏览器。 |
| **估时** | 1.5d（含便携浏览器体积评估） |

### TP-03「手机当扫码枪」目前没有兑现（且纯 HTTP 下做不到）

| 项 | 内容 |
|---|---|
| **现状** | Web 端无摄像头扫码（`web/src` 无 `getUserMedia`）；`android/` 只有一个 README。实际只支持 USB/蓝牙扫码枪与手输。 |
| **硬约束** | 浏览器要求 `getUserMedia` 运行在**安全上下文**：`http://localhost` 例外放行，但**手机访问 `http://192.168.x.x:5000` 不是安全上下文，摄像头会被直接拒绝**。因此"局域网 + 纯 HTTP"下手机浏览器摄像头扫码**不可行**，除非上 HTTPS 自签（手机需逐台信任，客户无法接受）或做安卓 App。`BarcodeDetector` 绕不过这条。 |
| **结论** | 这是**产品承诺问题**，不是排期问题。二选一：<br>**A（推荐，0 代码）**：文案改为「支持 USB/蓝牙扫码枪；手机/平板可当查询与开单终端」，主图去掉"手机摄像头扫码"；<br>**B（要投入）**：安卓 App（原生相机）列入 B3，或整站 HTTPS 自签（不推荐）。 |
| **可选加分** | PC 接 USB 摄像头，在 `localhost` 下用 `@zxing/browser` 扫码（纯 JS，无原生依赖）。仅解决"电脑没扫码枪"的少数场景。 |
| **验收** | 详情页/主图文案与实际能力一致；客服话术明确"需自备扫码枪"或"手机扫码需装 App（未发布）"。 |
| **估时** | 0.5d（文案与话术），不含选项 B |

### TP-04 没有试用机制，等于没有转化

| 项 | 内容 |
|---|---|
| **现状** | 授权 fail-closed：未激活时除激活页外全站 `1013`（`core/license_gate.py:22`），客户必须先付钱拿码才能看到界面。 |
| **风险** | 通用软件必须"先试后买"。没有试用，转化率与退货率双杀。 |
| **改法（推荐零代码）** | 沿用出码脚本 `scripts/make-dev-license.py`，发货流程直接发**15 天有效期试用码**（授权协议已支持到期时间戳 `x`）。卖家侧建一张 Excel 客户台账（机器码 / 出码时间 / 到期 / 是否转正）。 |
| **改法（体验加分，0.5d）** | 登录页与顶栏显示"授权剩余 N 天"；到期前 7 天每日提醒一次；到期后**转只读**（能看能导出、不能写），不要直接锁死——锁死会让客户以为数据丢了。 |
| **换机迁移** | 一机一码，换机重新出码。详情页写明「免费换机 3 次，提供新机器码即可」。不做自助解绑（防破解成本高于收益）。 |
| **验收** | 新机器用 15 天码可完整体验；到期按约定降级；换机 1 次沟通内完成。 |
| **估时** | 0.5d（仅做剩余天数提示时） |

### TP-05 PyInstaller 未签名，360/火绒大概率报毒

| 项 | 内容 |
|---|---|
| **现状** | onedir + 未签名 exe。 |
| **风险** | 淘宝软件"装不上"的第一原因，比功能缺失更致命。 |
| **改法** | ① 优先买**代码签名证书**（OV 即可）对 exe 与安装包签名，这是唯一根治办法；② 短期兜底：首启弹"安全提示"图文（加入信任/恢复区），详情页提前说明；③ 提交 360/火绒/腾讯白名单申诉（免费，周期 1~2 周）；④ 安装包做成一键安装（Inno Setup，仅构建机依赖），不要扔 zip 让客户找 exe。 |
| **验收** | 干净 Win7 + 360 全盘开启：下载→安装→启动→登录全程无拦截；若有拦截，3 步内可放行。 |
| **估时** | 2d（不含证书采购等待） |

### TP-06 没有诊断包，客服只能靠截图猜

| 项 | 内容 |
|---|---|
| **现状** | 有日志与备份，但没有"一键导出诊断信息"的入口与接口。 |
| **风险** | 每个售后问题多花 20~30 分钟，且常问不出关键信息（版本、端口、库大小、trace_id）。 |

| **验收** | 一键下载，解压 5 个文件齐全且无敏感信息；凭该包能判断"版本过低/端口不通/库损坏"。 |
| **估时** | 0.5d |

## 3. B1 · 能用（6.5 人日）

### TP-07 商品档案撑不住"通用"二字

| 项 | 内容 |
|---|---|
| **现状** | `products` 只有 `name / barcode / category / unit / cost_price / sale_price / min_stock / remark`：一条商品一个条码、一个单位、无规格型号、无图片、数量只能整数、分类是自由文本。 |
| **风险** | 服装（颜色尺码）、五金（kg/米）、电商（SKU 上千、一码多品）一上手就"建不了档"，直接退款。 |
| **拆解** | 以下 4 个子项可独立交付，建议按 a→b→c→d 顺序。 |

**TP-07a 多规格：`products.parent_id` 自关联（推荐，1.5d）**

- `products` 增 `parent_id INTEGER NOT NULL DEFAULT 0`（0=单品/主商品；非 0=该主商品下的 SKU 行）。
- **不给 `stock_current` / `stock_logs` 加维度**：SKU 行本身就是一条 `products` 记录，库存主键仍是 `(product_id, warehouse_id)`。账本、并发、触发器、报表、对账**全部不动**——这是本方案最大的价值点。
- 约束：存在子行时父商品禁止扫码/出入库（`1004` 语义提示）；删除父商品前必须无子行；列表默认按父商品聚合、可展开。
- 扫码命中 SKU 行，返回带父商品名，界面显示「T恤 / 黑色 XL」。
- 需新增迁移 `0008_product_generalization.sql`，同步 `docs/02` 与 `schema.sql`，递增 `schema_meta.version`。

**TP-07b 一品多码：`product_barcodes`（1d）**

```text
product_barcodes(id, product_id, barcode UNIQUE, kind CHECK IN ('PRIMARY','CASE','SUPPLIER'),
                 factor INTEGER NOT NULL DEFAULT 1, is_active, created_at, updated_at)
```

- `kind=CASE` 的 `factor` = "扫一箱 = N 件"（扫码台自动乘数量，允许手改）。
- **解析顺序**：先查 `products.barcode`，再查 `product_barcodes.barcode`，都未命中才 `1007`。
- ★ 唯一性必须在**服务层跨两张表**校验（两表条码不得重复），数据库唯一索引只管表内。
- `GET /api/products/by-barcode/<barcode>` 返回增加 `matched_kind` / `factor` / `parent_name`。

**TP-07c 商品图片（0.5d）**

- `products` 增 `image_path TEXT`，**只存相对文件名**，文件落 `%LOCALAPPDATA%\ScanableSelf\images\`。
- 新增 `GET /api/products/<id>/image`（`require_login`）；上传限 2MB，白名单 `jpg/jpeg/png/webp`，服务端校验扩展名与实际文件头，禁止路径穿越。
- 前端用 blob URL 展示（同 `Labels.tsx` 的条码图做法），不要 `<img src>` 直接带 Token。

**TP-07d 小数数量：`qty_scale`（1d，不改 `quantity` 语义）**

- `products` 增 `qty_scale INTEGER NOT NULL DEFAULT 1 CHECK (qty_scale IN (1,10,100,1000))`，表示 1 个展示单位 = N 个最小单位。
- 数据库里 `quantity` **仍是整数最小单位**：1.25 kg（scale=100）存 `125`。条件更新、CHECK、触发器、并发判定、幂等**全部不改**。
- 前端按 `qty_scale` 录入与展示；后端 DTO 带 `qty_scale`；`422/1009` 里的 `current/requested/lack` 也用最小单位下发，由前端换算——**不要**在后端做除法再取整。
- ★ **有流水后禁止修改 `qty_scale`**（服务层 `409`）：`stock_logs` 没有 scale 快照，改了会让历史流水显示错位。这条约束必须写进界面提示与测试。
- `qty_scale` 与 `docs/14` P2-D 的"箱/件换算"不同：前者只是"同单位允许小数"，后者仍留 B3。

**TP-07 总验收**

- 建一个"T恤（3 色 × 3 码）"主商品 + 9 个 SKU，各扫一次入库；库存按 SKU 独立，列表可聚合。
- 同一 SKU 绑 2 个条码（主码 + 箱码 factor=12），扫箱码入库数量自动为 12。
- 建一个 scale=100 的"螺丝"，入库 1.25，库存显示 1.25，导出 CSV 也是 1.25。
- 上传商品图片后，列表、详情、扫码结果都能看到。

**TP-07 估时合计：4d**

### TP-08 扫码台的出入库不能填实际单价

| 项 | 内容 |
|---|---|
| **现状** | `services/stock_service.py:181` 直接取档案价（`cost_price` / `sale_price`），请求里的价格被忽略。 |
| **风险** | 进货价随行就市时，成本均价、库存金额、毛利全部失真。而扫码台是通用客户用得最多的入口。 |
| **改法** | `POST /api/stock/in` 与 `POST /api/stock/out` 接受可选 `unit_price`：留空回落档案价；填入则校验 `>=0` 且 `<=1000000`，写流水时 `amount = qty * price`。入库同时更新移动加权（已有 `cost_service`）。前端扫码台加"单价"输入（默认带出档案价，可改）。 |
| **注意** | 单据过账路径已带实际价，不受影响；本项只补扫码台。ADJUST 仍不允许填价。 |
| **验收** | 扫码入库 10 件、单价 8.5（档案价 10）→ 流水金额 85、均价按 8.5 重算；留空则用 10。 |
| **估时** | 0.5d |

### TP-09 报表看不到钱

| 项 | 内容 |
|---|---|
| **现状** | 有 `avg_cost`，但库存页/导出/汇总不出金额；`summarize()` 只统计 IN/OUT，**ADJUST 完全不计入**，导致"入库−出库≠库存变化"；无期初/期末；无库龄。 |
| **风险** | 老板第一问"库存值多少钱"答不出；对账时数字对不上，直接失去信任。 |
| **改法（纯查询层，不动表）** | ① 库存页与导出增加 `qty × avg_cost` 金额列与合计；② 汇总报表补 `ADJUST` 正/负列，并给出`期初 + IN − OUT ± ADJUST = 期末`四栏；③ 库龄按 `stock_current.last_in_at` 分档（30/60/90/180+）；④ 滞销 = 90 天无出库且有库存。 |
| **口径要求** | 期初 = 期间开始前的累计；`ref_type='OPENING'` 单列，不混入采购统计（`docs/14` 3.6 约束）。 |
| **验收** | 任选一个仓库 + 月度区间，手工按流水算出的期末与报表一致；ADJUST 后报表能解释差异。 |
| **估时** | 1.5d |

## 9. 淘宝详情页话术边界（建议直接采用）

**能写**：局域网本地部署、数据不上传、扫码枪出入库、多仓库、盘点、领用借用、采购销售单据、打印标签与 A4 单据、CSV/Excel 导入导出、一机一码离线授权、Win7 可用。

**不能写**（写了就是描述不符）：
- "手机摄像头扫码"（除非 TP-03 选 B 并已交付）
- "支持序列号追溯 / 批次保质期"
- "支持称重 / 小数计量"（TP-07d 上线前）
- "对接淘宝/拼多多订单、自动打单"
- "多人异地协同 / 云同步"

**建议加一行**："本软件为局域网单机版，不支持外网访问；购买前请确认您的电脑为 Windows 7 SP1 及以上，并使用 Chrome/Edge/360 极速模式。"
