# 02 · 数据模型（唯一权威 DDL）

> 本文件的 SQL 与 `desktop/db/schema.sql` **必须逐字一致**。改表先改本文件与迁移脚本，再改代码。
> 章节引用见 `01-产品需求文档.md` 第 4 章。

---

## 1. PRAGMA（每连接必须执行）

```sql
-- 文件级持久：
PRAGMA journal_mode = WAL;        -- 读写不互斥。禁止在网络盘（SMB/NAS）上启用 WAL
PRAGMA page_size = 4096;

-- 连接级（不持久化，每次 connect 后必须重设）：
PRAGMA foreign_keys = ON;         -- SQLite 默认关闭！不开则外键形同虚设
PRAGMA busy_timeout = 5000;       -- 写锁排队 5s，避免直接 database is locked
PRAGMA synchronous = FULL;        -- 宁慢不丢。禁止改 NORMAL
```

**实现要求**：以上四项统一封装在 `desktop/models/database.py:get_connection()`，业务代码**禁止**自行 `sqlite3.connect()`。

## 2. 完整 DDL

```sql
-- =====================================================================
-- ScanableSelf WMS MVP · schema v1
-- 约定：INTEGER 主键 AUTOINCREMENT；时间 TEXT ISO-8601 东八区带偏移；
--       布尔 INTEGER 0/1；枚举大写（角色小写 admin/operator 例外）
-- =====================================================================

CREATE TABLE IF NOT EXISTS schema_meta (
    version     INTEGER PRIMARY KEY,            -- 迁移版本号，与 migrations/NNNN_*.sql 对应
    applied_at  TEXT    NOT NULL                -- 执行时间
);
-- 用途：记录已到版本；迁移只能顺序追加，禁止修改历史迁移文件

CREATE TABLE IF NOT EXISTS users (
    id                   INTEGER PRIMARY KEY AUTOINCREMENT,
    username             TEXT    NOT NULL UNIQUE,           -- 登录名，2~32 位 [0-9A-Za-z_.]
    display_name         TEXT,                              -- 显示名，可空
    password_hash        TEXT    NOT NULL,                  -- pbkdf2:sha256:600000$...；日志必须脱敏
    role                 TEXT    NOT NULL DEFAULT 'operator'
                         CHECK (role IN ('admin','operator')),
    is_active            INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
    must_change_password INTEGER NOT NULL DEFAULT 0 CHECK (must_change_password IN (0,1)),
    created_at           TEXT    NOT NULL,
    updated_at           TEXT    NOT NULL,
    last_login_at        TEXT                                -- NULL=从未登录
);
-- 级联：被 api_tokens CASCADE 引用、被 stock_logs RESTRICT 引用

CREATE TABLE IF NOT EXISTS api_tokens (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,  -- 理由：删账号即踢设备，Token 无保留价值
    token_hash   TEXT    NOT NULL UNIQUE,                   -- SHA-256(token)；明文只在登录响应中出现一次
    client_type  TEXT    NOT NULL DEFAULT 'android'
                 CHECK (client_type IN ('android','web','pda')),
    device_name  TEXT,                                      -- 手机型号/别名，供 admin 辨认
    created_at   TEXT    NOT NULL,
    last_used_at TEXT,
    expires_at   TEXT,                                      -- NULL=永不过期（自用默认 90 天后填值）
    revoked_at   TEXT                                       -- 非 NULL=已吊销，保留记录供审计 90 天
);
CREATE INDEX IF NOT EXISTS idx_tokens_user ON api_tokens(user_id, revoked_at);

CREATE TABLE IF NOT EXISTS warehouses (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    code       TEXT    UNIQUE,                                -- 仓库编码（0002 新增，可空；历史行不回填）
    name       TEXT    NOT NULL UNIQUE CHECK (length(name) BETWEEN 1 AND 30),
    parent_id  INTEGER NOT NULL DEFAULT 0,                    -- 0=顶级（0002 新增，两级树：见下方说明）
    level      INTEGER NOT NULL DEFAULT 1,                    -- 1=仓库 2=库位（0002 新增）
    category   TEXT,                                          -- 仓库类型编码（0002 新增，大写枚举）
    address    TEXT,
    is_active  INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at TEXT    NOT NULL,
    updated_at TEXT    NOT NULL
);
-- 删除规则：有库存余额（stock_current.qty!=0）时禁止删除；实现为应用层 409 + RESTRICT
-- 树形规则（0002）：最多两级（level<=2）；parent_id 必须指向存在的 level=1 仓库；
--   禁止自环、禁止把父仓库挂到自己的子孙下；有子库位的仓库禁止删除/停用（应用层 409，docs/13 第 4.1 节）。
-- ★ parent_id 用 0 表示顶级而不是 NULL：避免「外键指向不存在」与「NULL 比较不生效」两类经典错误。
CREATE UNIQUE INDEX IF NOT EXISTS idx_warehouses_code   ON warehouses(code);
CREATE INDEX        IF NOT EXISTS idx_warehouses_parent ON warehouses(parent_id, is_active);

CREATE TABLE IF NOT EXISTS partners (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    name       TEXT    NOT NULL CHECK (length(name) BETWEEN 1 AND 50),
    type       TEXT    NOT NULL CHECK (type IN ('CUSTOMER','SUPPLIER')),
    contact    TEXT,
    phone      TEXT,                     -- 业务数据，非自然人身份信息系统；提示勿录无关他人信息
    address    TEXT,
    remark     TEXT,
    is_active  INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
    created_at TEXT    NOT NULL,
    updated_at TEXT    NOT NULL,
    UNIQUE (name, type)                  -- 防止把同一客户登记两遍
);
CREATE INDEX IF NOT EXISTS idx_partners_type ON partners(type, is_active);

CREATE TABLE IF NOT EXISTS products (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    name         TEXT    NOT NULL CHECK (length(name) BETWEEN 1 AND 100),
    barcode      TEXT    UNIQUE,        -- 规范化后 3~48 位 [0-9A-Za-z-]；NULL=无条码商品
                                        -- 软删除后条码永久占用，不得复用（防数据串号）
    category     TEXT    DEFAULT '未分类',
    unit         TEXT    NOT NULL DEFAULT '件',
    cost_price   REAL    NOT NULL DEFAULT 0 CHECK (cost_price >= 0),
    sale_price   REAL    NOT NULL DEFAULT 0 CHECK (sale_price >= 0),
    min_stock    INTEGER NOT NULL DEFAULT 0 CHECK (min_stock >= 0),   -- 低于此值进预警
    remark       TEXT,
    is_active    INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)), -- 0=软删除
    deleted_at   TEXT,
    created_at   TEXT    NOT NULL,
    updated_at   TEXT    NOT NULL       -- 兼作乐观锁版本（PUT 必须回传比对）
);
CREATE INDEX IF NOT EXISTS idx_products_name     ON products(name);
CREATE INDEX IF NOT EXISTS idx_products_category ON products(category, is_active);
CREATE INDEX IF NOT EXISTS idx_products_active   ON products(is_active, id);

-- ================= 核心账本表 =================
CREATE TABLE IF NOT EXISTS stock_logs (
    id                    INTEGER PRIMARY KEY AUTOINCREMENT,
    client_msg_id         TEXT    NOT NULL UNIQUE,  -- ★幂等生命线：APP/网页生成 UUID v4(≤36)
                                                    -- 重复提交命中 UNIQUE → 返回首次结果，不报错
    product_id            INTEGER NOT NULL REFERENCES products(id)   ON DELETE RESTRICT,
    warehouse_id          INTEGER NOT NULL REFERENCES warehouses(id) ON DELETE RESTRICT,
    operator_id           INTEGER NOT NULL REFERENCES users(id)      ON DELETE RESTRICT,
    partner_id            INTEGER          REFERENCES partners(id)   ON DELETE SET NULL,
    type                  TEXT    NOT NULL CHECK (type IN ('IN','OUT','ADJUST')),
    quantity              INTEGER NOT NULL CHECK (
                              (type IN ('IN','OUT') AND quantity > 0)
                           OR (type = 'ADJUST'     AND quantity != 0)
                          ),
        -- 方向必须由 type 表达：IN/OUT 恒正；ADJUST 可正可负但不得为 0。
        -- 库级锁定，服务层校验只是第二道（误写的 SQL / AI 生成的批量语句挡不住）
    before_qty            INTEGER NOT NULL,          -- ★快照：写入前该商品在该仓库的库存
    after_qty             INTEGER NOT NULL,          -- ★快照：写入后库存
    product_name_snapshot TEXT    NOT NULL,          -- ★快照：防止商品改名后历史报表失真
    unit_price            REAL,                      -- 结算价：IN 取成本价，OUT 取售价（NULL=不适用）
    amount                REAL,                      -- = abs(quantity) * unit_price，冗余存储便于汇总
    unit_cost             REAL,                      -- 0007 新增：成本单价（系统算，业务不得填，docs/14 7.1）
    cost_amount           REAL,                      -- 0007 新增：= abs(quantity) * unit_cost
    source                TEXT    NOT NULL DEFAULT 'WEB' CHECK (source IN ('WEB','APP','PDA')),
    device_name           TEXT,                      -- APP 侧设备名，便于追溯
    remark                TEXT,                      -- ADJUST 必填；冲销写 REVERSAL_OF:#<log_id>
    reversed_by           INTEGER,                   -- 指向冲销生成的那条流水 id（NULL=未被冲销）
    ref_type              TEXT,                      -- 0002 新增：溯源类型（单据见 docs/13 4.6；期初='OPENING'）
    ref_id                INTEGER,                   -- 0002 新增：对应单据 id（期初固定 0 占位）；二者同有同无
    trace_id              TEXT,                      -- 与日志同源，8 位，用于问题回溯
    created_at            TEXT    NOT NULL           -- 业务发生时间（APP 离线时为本地扫码时刻）
);
-- ★ ref_type/ref_id 不在 trg_logs_immutable 的锁定列清单内（只锁账目语义列），
--   因此 0002 能用 ALTER TABLE ADD COLUMN 直接加列，历史行自动为 NULL（=非单据产生的流水）。
CREATE INDEX IF NOT EXISTS idx_logs_created     ON stock_logs(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_logs_product     ON stock_logs(product_id, warehouse_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_logs_type_date   ON stock_logs(type, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_logs_operator    ON stock_logs(operator_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_logs_warehouse   ON stock_logs(warehouse_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_logs_partner     ON stock_logs(partner_id);
-- 说明：idx_logs_type_date / idx_logs_partner 服务仪表盘与报表的 WHERE/GROUP BY；
--       created_at DESC 索引服务「默认倒序取最近 N 条」这一最高频访问模式

-- ============ 账本不可变性（DB 级硬约束）============
-- 外键 RESTRICT 只保护父记录（删商品/仓库/用户会被拒），**并不阻止删除或篡改流水本身**。
-- 因此账本保护必须由触发器承担：任何代码路径（含误写的 SQL、AI 生成的批量清理）都无法抹掉历史。
-- 允许的更正方式只有两种：红字冲销（INSERT 反向行）、ADJUST 盘点（INSERT 调整行）。
CREATE TRIGGER IF NOT EXISTS trg_logs_no_delete
BEFORE DELETE ON stock_logs
BEGIN
    SELECT RAISE(ABORT, 'stock_logs 是账本：禁止物理删除历史行（错单请用红字冲销，账实不符请用 ADJUST）');
END;

-- 仅锁定「账目语义」列；reversed_by / remark 允许更新（冲销需要回写 reversed_by 指针）。
CREATE TRIGGER IF NOT EXISTS trg_logs_immutable
BEFORE UPDATE OF type, quantity, before_qty, after_qty, product_id, warehouse_id,
                 client_msg_id, product_name_snapshot, operator_id, source, created_at,
                 unit_price, amount, unit_cost, cost_amount
ON stock_logs
BEGIN
    SELECT RAISE(ABORT, 'stock_logs 是账本：禁止修改历史行的账目字段（更正请用红字冲销或 ADJUST）');
END;
-- ★ 给 stock_logs 加列的迁移必须 DROP + CREATE 本触发器（BEFORE UPDATE OF 的列清单是静态枚举），
--   否则新列可被 UPDATE 静默篡改（0007 即按此重建）。

-- ================= 派生表（可由流水全量重算） =================
CREATE TABLE IF NOT EXISTS stock_current (
    product_id   INTEGER NOT NULL REFERENCES products(id)   ON DELETE CASCADE,  -- 理由：纯派生数据，随主数据清理，可重算
    warehouse_id INTEGER NOT NULL REFERENCES warehouses(id) ON DELETE CASCADE,
    qty          INTEGER NOT NULL DEFAULT 0,      -- 正常应 >=0；出现负数即为数据异常，UI 必须标红不得掩盖
    avg_cost     REAL    NOT NULL DEFAULT 0,      -- 0007 新增：移动加权单价（金额 = qty*avg_cost，现算不存）
    updated_at   TEXT    NOT NULL,
    PRIMARY KEY (product_id, warehouse_id)
);
CREATE INDEX IF NOT EXISTS idx_stock_wh ON stock_current(warehouse_id, qty);   -- 服务「按仓库看库存」与预警 JOIN

CREATE TABLE IF NOT EXISTS settings (
    key        TEXT PRIMARY KEY,
    value      TEXT NOT NULL,
    value_type TEXT NOT NULL DEFAULT 'string' CHECK (value_type IN ('string','int','bool','json')),
    updated_at TEXT NOT NULL,
    updated_by INTEGER REFERENCES users(id) ON DELETE SET NULL
);

-- ================= 单据层（0003 迁移，docs/13 第 4.2 / 4.3 节） =================
-- 单据只管「要收多少 / 收了多少」；库存一律由 services/stock_service.post_bill_lines
-- 落到 stock_logs + stock_current，流水带 ref_type/ref_id 指回单据。
CREATE TABLE IF NOT EXISTS wms_purchase_order (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    code              TEXT    NOT NULL UNIQUE,          -- PO + yyyymmdd + 4 位流水
    name              TEXT    NOT NULL,
    applicant_user_id INTEGER NOT NULL REFERENCES users(id)    ON DELETE RESTRICT,
    partner_id        INTEGER          REFERENCES partners(id) ON DELETE RESTRICT,  -- 须为 SUPPLIER
    partner_name_snap TEXT,                              -- ★快照
    applicant_date    TEXT    NOT NULL,
    total_qty         INTEGER NOT NULL DEFAULT 0,
    total_amount      REAL    NOT NULL DEFAULT 0,
    status            TEXT    NOT NULL DEFAULT 'DRAFT'
                      CHECK (status IN ('DRAFT','SUBMITTED','APPROVED','REJECTED','CLOSED','CANCELED')),
    submit_at         TEXT,
    approve_at        TEXT,
    approver_id       INTEGER REFERENCES users(id) ON DELETE RESTRICT,
    reject_reason     TEXT,
    remark            TEXT,
    is_active         INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),  -- 0=作废（软删）
    created_at        TEXT    NOT NULL,
    updated_at        TEXT    NOT NULL                   -- 兼作乐观锁版本
);
CREATE INDEX IF NOT EXISTS idx_wpo_status  ON wms_purchase_order(status, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_wpo_partner ON wms_purchase_order(partner_id);

CREATE TABLE IF NOT EXISTS wms_purchase_order_detail (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id          INTEGER NOT NULL REFERENCES wms_purchase_order(id) ON DELETE CASCADE,
    product_id        INTEGER NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
    product_name_snap TEXT    NOT NULL,                  -- ★快照
    barcode_snap      TEXT,
    unit_snap         TEXT    NOT NULL,
    price             REAL    NOT NULL DEFAULT 0 CHECK (price >= 0),
    qty               INTEGER NOT NULL CHECK (qty > 0),
    amount            REAL    NOT NULL DEFAULT 0,        -- = price * qty
    received_qty      INTEGER NOT NULL DEFAULT 0,        -- 累计入库（过账时条件更新回写，≤ qty）
    sort_order        INTEGER NOT NULL DEFAULT 0,
    remark            TEXT,
    created_at        TEXT    NOT NULL,
    updated_at        TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_wpod_order ON wms_purchase_order_detail(order_id, sort_order);

CREATE TABLE IF NOT EXISTS wms_purchase_in_warehousing (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    code              TEXT    NOT NULL UNIQUE,          -- PI + yyyymmdd + 4 位流水
    name              TEXT    NOT NULL,
    order_id          INTEGER          REFERENCES wms_purchase_order(id) ON DELETE RESTRICT,  -- 可空=无源单直接入库
    order_code_snap   TEXT,
    warehouse_id      INTEGER NOT NULL REFERENCES warehouses(id) ON DELETE RESTRICT,
    partner_id        INTEGER          REFERENCES partners(id)   ON DELETE RESTRICT,
    in_date           TEXT    NOT NULL,
    total_qty         INTEGER NOT NULL DEFAULT 0,
    total_amount      REAL    NOT NULL DEFAULT 0,
    status            TEXT    NOT NULL DEFAULT 'DRAFT'
                      CHECK (status IN ('DRAFT','SUBMITTED','APPROVED','REJECTED','CANCELED')),
    posted_at         TEXT,                              -- ★非空=已过账（此刻写了 stock_logs）
    posted_by         INTEGER REFERENCES users(id) ON DELETE RESTRICT,
    submit_at         TEXT,
    approve_at        TEXT,
    approver_id       INTEGER REFERENCES users(id) ON DELETE RESTRICT,
    reject_reason     TEXT,
    remark            TEXT,
    is_active         INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
    created_at        TEXT    NOT NULL,
    updated_at        TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_wpi_status ON wms_purchase_in_warehousing(status, in_date DESC);
CREATE INDEX IF NOT EXISTS idx_wpi_order  ON wms_purchase_in_warehousing(order_id);

CREATE TABLE IF NOT EXISTS wms_purchase_in_warehousing_detail (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    inbound_id        INTEGER NOT NULL REFERENCES wms_purchase_in_warehousing(id) ON DELETE CASCADE,
    order_detail_id   INTEGER          REFERENCES wms_purchase_order_detail(id)   ON DELETE SET NULL,
    product_id        INTEGER NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
    product_name_snap TEXT    NOT NULL,
    unit_snap         TEXT    NOT NULL,
    qty               INTEGER NOT NULL CHECK (qty > 0),
    price             REAL    NOT NULL DEFAULT 0 CHECK (price >= 0),
    amount            REAL    NOT NULL DEFAULT 0,
    sort_order        INTEGER NOT NULL DEFAULT 0,
    remark            TEXT,
    created_at        TEXT    NOT NULL,
    updated_at        TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_wpid_inbound ON wms_purchase_in_warehousing_detail(inbound_id, sort_order);

-- ================= 通用操作单（0004 迁移，docs/13 第 4.4 / 4.6 节） =================
-- 五种 op_type 共用一个主子表；过账方向见 docs/13 4.6 映射表（RECEIVE/BORROW→OUT，
-- RETURN_STOCK/RETURN_BORROW→IN，TRANSFER→源仓 OUT + 目标仓 IN）。
CREATE TABLE IF NOT EXISTS wms_goods_operation_order (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    code               TEXT    NOT NULL UNIQUE,          -- GO + yyyymmdd + 4 位流水
    name               TEXT    NOT NULL,
    op_type            TEXT    NOT NULL
                       CHECK (op_type IN ('RECEIVE','RETURN_STOCK','RETURN_BORROW','BORROW','TRANSFER')),
    order_id           INTEGER          REFERENCES wms_purchase_order(id) ON DELETE RESTRICT,
    in_warehousing_id  INTEGER          REFERENCES wms_purchase_in_warehousing(id) ON DELETE RESTRICT,
    warehouse_id       INTEGER NOT NULL REFERENCES warehouses(id) ON DELETE RESTRICT,  -- 源仓库
    to_warehouse_id    INTEGER          REFERENCES warehouses(id) ON DELETE RESTRICT,  -- 调拨目标仓
    operator_user_id   INTEGER NOT NULL REFERENCES users(id) ON DELETE RESTRICT,       -- 领用/借用/归还人
    partner_id         INTEGER          REFERENCES partners(id) ON DELETE RESTRICT,
    op_date            TEXT    NOT NULL,
    expect_return_date TEXT,                             -- 借用必填
    total_qty          INTEGER NOT NULL DEFAULT 0,
    total_amount       REAL    NOT NULL DEFAULT 0,
    status             TEXT    NOT NULL DEFAULT 'DRAFT'
                       CHECK (status IN ('DRAFT','SUBMITTED','APPROVED','REJECTED','DONE','REVERSED','CANCELED')),
    posted_at          TEXT,                             -- 非空=已过账
    posted_by          INTEGER REFERENCES users(id) ON DELETE RESTRICT,
    submit_at          TEXT,
    approve_at         TEXT,
    approver_id        INTEGER REFERENCES users(id) ON DELETE RESTRICT,
    reject_reason      TEXT,
    reversed_at        TEXT,                             -- 冲销时刻（对已过账流水逐条红字冲销）
    reversed_by        INTEGER REFERENCES users(id) ON DELETE RESTRICT,
    remark             TEXT,
    is_active          INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
    created_at         TEXT    NOT NULL,
    updated_at         TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_wgo_status ON wms_goods_operation_order(status, op_date DESC);
CREATE INDEX IF NOT EXISTS idx_wgo_type   ON wms_goods_operation_order(op_type, status);

CREATE TABLE IF NOT EXISTS wms_goods_operation_detail (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id          INTEGER NOT NULL REFERENCES wms_goods_operation_order(id) ON DELETE CASCADE,
    product_id        INTEGER NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
    product_name_snap TEXT    NOT NULL,
    barcode_snap      TEXT,
    unit_snap         TEXT    NOT NULL,
    qty               INTEGER NOT NULL CHECK (qty > 0),
    price             REAL,                              -- 可空：领用/借用可能不计价
    amount            REAL,
    serial_number     TEXT,
    is_join_asset     INTEGER NOT NULL DEFAULT 0 CHECK (is_join_asset IN (0,1)),  -- 只标记，不建资产表
    sort_order        INTEGER NOT NULL DEFAULT 0,
    remark            TEXT,
    created_at        TEXT    NOT NULL,
    updated_at        TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_wgod_order ON wms_goods_operation_detail(order_id, sort_order);
CREATE INDEX IF NOT EXISTS idx_wgod_sn    ON wms_goods_operation_detail(serial_number);
```

## 3. 种子数据（`manage.py initdb`，按 FK 正序插入）

```sql
INSERT INTO schema_meta(version, applied_at) VALUES (1, '<now_iso>');
INSERT INTO users(username, display_name, password_hash, role, must_change_password, created_at, updated_at)
VALUES ('admin', '系统管理员', '<pbkdf2(admin123)>', 'admin', 1, '<now_iso>', '<now_iso>');
INSERT INTO warehouses(name, is_active, sort_order, created_at, updated_at)
VALUES ('主仓库', 1, 0, '<now_iso>', '<now_iso>');
-- settings 默认 12 项，见 01-PRD 第 20 章，全部 INSERT OR IGNORE（可重复执行）
```

**测试数据清理顺序（FK 逆序，`conftest.py` autouse fixture 必须照此实现）**：
`stock_logs → stock_current → settings → products → partners → warehouses → api_tokens → users → schema_meta`

## 4. 无 JSON 字段的说明

本 schema **不使用** JSON/JSONB 列。理由：SQLite 的 JSON 函数需 `json_each` 解析、无法建索引、安卓侧序列化成本高，而本项目的结构化需求已全部由关系表覆盖。唯一例外预留：`settings.value` 当 `value_type='json'` 时存 JSON 字符串（仅用于未来的打印模板配置，V1 未使用）。若 V2 需要，示例结构：

```json
{"label_size":"40x30","show_name":true,"show_price":false,"font_scale":1.0,"columns":2,"rows":5}
```

## 5. 一致性保障与自检 SQL

**铁律**：写 `stock_logs` 与更新 `stock_current` 必须在同一事务，用 SAVEPOINT 实现批量错误隔离（见 04 文档 T-08）。

**不变式**（任何时候都应成立；违反即 L3 降级）：

```sql
-- 检查 1：派生表与流水聚合是否一致（recalc-stock 的核心逻辑）
SELECT sc.product_id, sc.warehouse_id, sc.qty AS recorded,
       COALESCE(SUM(CASE l.type WHEN 'IN' THEN l.quantity
                                WHEN 'OUT' THEN -l.quantity
                                ELSE l.quantity END), 0) AS computed
  FROM stock_current sc
  LEFT JOIN stock_logs l ON l.product_id=sc.product_id AND l.warehouse_id=sc.warehouse_id
 GROUP BY sc.product_id, sc.warehouse_id, sc.qty
HAVING recorded != computed;
-- 期望：0 行。有输出 = 数据异常，逐条排查（禁止手工 UPDATE 库，用 ADJUST 修正）

-- 检查 2：是否存在负库存（异常数据）
SELECT * FROM stock_current WHERE qty < 0;

-- 检查 3：流水快照自洽（before/after 与 quantity 关系）
SELECT id, type, quantity, before_qty, after_qty FROM stock_logs
 WHERE (type='IN'  AND after_qty != before_qty + quantity)
    OR (type='OUT' AND after_qty != before_qty - quantity)
    OR (type='ADJUST' AND after_qty != before_qty + quantity);
-- 期望：0 行

-- 检查 4：孤儿与悬空（外键完整性）
PRAGMA foreign_key_check;   -- 期望：无输出

-- 检查 5：单据溯源完整性（0002 起）：ref_type 与 ref_id 必须同有同无
SELECT id, ref_type, ref_id FROM stock_logs
 WHERE (ref_type IS NULL) <> (ref_id IS NULL);
-- 期望：0 行。有输出 = 过账代码漏写一半，属 L3 级缺陷
-- ★ 期初建账（ref_type='OPENING'）不指向单据，按约定写 ref_id=0 占位：
--   0 不是 NULL，同有同无成立；按 ref_type 聚合的采购/销售报表必须把 OPENING 单列或排除。
-- ★ ref_type 白名单：BILL_REF_TYPES（库存同源单据：PURCHASE_IN/RECEIVE/RETURN_STOCK/RETURN_BORROW/
--   BORROW/TRANSFER_OUT/TRANSFER_IN/SALES_OUT/SALES_RETURN）+ OPENING（期初）+ STOCKTAKE（盘点），
--   见 services/stock_service.py:LOG_REF_TYPES。

-- 检查 6（0007 起）：成本重放一致性 —— 按 created_at,id 重放全量流水后，
--   stock_current.avg_cost 必须与重放结果一致（实现见 models/stock_repo.py:recompute_from_logs，
--   由 `manage.py recalc-stock` 与 `GET /api/backup/recalc` 共用）。
--   期望：0 行。有输出 = 成本口径被绕过写入（必须用 recalc-stock --apply 修复，禁止手工改库）。
```

## 5.6 盘点单 DDL（0005 迁移，与 `db/schema.sql` 逐字一致）

> 依据 `docs/14` 第 4.4 节。盘点单是第四类单据（PO / PI / GO / **ST**）。
> ★ 明细不加 `warehouse_id`：整单一个仓库，冗余列会制造第二处真相。
> ★ `book_qty` 只是建单快照，用于差异报表；**过账数量按实时当前值算**（docs/14 4.3 B 口径）。

```sql
-- 盘点单：第四类单据（采购订单 PO / 采购入库 PI / 通用操作 GO / 盘点 ST）
CREATE TABLE IF NOT EXISTS wms_stocktake (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    code           TEXT    NOT NULL UNIQUE,          -- ST + yyyymmdd + 4 位流水
    name           TEXT    NOT NULL CHECK (length(name) BETWEEN 1 AND 50),
    warehouse_id   INTEGER NOT NULL REFERENCES warehouses(id) ON DELETE RESTRICT,
    scope_category TEXT,                             -- 生成时的分类筛选（仅记录，不参与过账）
    status         TEXT    NOT NULL DEFAULT 'DRAFT'
                   CHECK (status IN ('DRAFT','SUBMITTED','REJECTED','POSTED','CANCELED')),
    book_locked_at TEXT    NOT NULL,                 -- 快照时刻（账面基准时间）
    posted_at      TEXT,                             -- 过账时刻
    operator_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    submitter_id   INTEGER REFERENCES users(id) ON DELETE SET NULL,
    approver_id    INTEGER REFERENCES users(id) ON DELETE SET NULL,
    remark         TEXT,
    created_at     TEXT    NOT NULL,
    updated_at     TEXT    NOT NULL,
    -- 状态与时间戳必须自洽，防止"已过账但没 posted_at"这类半截状态
    CHECK ((status = 'POSTED') = (posted_at IS NOT NULL))
);
CREATE INDEX IF NOT EXISTS idx_stocktake_status ON wms_stocktake(status, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_stocktake_wh     ON wms_stocktake(warehouse_id, created_at DESC);

CREATE TABLE IF NOT EXISTS wms_stocktake_detail (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    stocktake_id  INTEGER NOT NULL REFERENCES wms_stocktake(id) ON DELETE CASCADE,
    product_id    INTEGER NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
    book_qty      INTEGER NOT NULL DEFAULT 0,        -- 快照账面数
    real_qty      INTEGER,                          -- 实盘数（NULL = 未盘，不参与过账）
    diff_qty      INTEGER NOT NULL DEFAULT 0,        -- real_qty - book_qty（录入时算好存下）
    product_name_snapshot TEXT NOT NULL,             -- 防改名（与 stock_logs 同口径）
    remark        TEXT,
    created_at    TEXT    NOT NULL,
    UNIQUE (stocktake_id, product_id),
    CHECK (real_qty IS NULL OR real_qty >= 0)
);
CREATE INDEX IF NOT EXISTS idx_stocktake_detail_st ON wms_stocktake_detail(stocktake_id);
```

## 5.7 销售订单 / 销售退货 DDL（0006 迁移，与 `db/schema.sql` 逐字一致）

> 依据 `docs/14` 第 6 章（P1-4）。逐列对齐采购侧（`wms_purchase_order` / `wms_purchase_return`），差异只在下面四处：
> ★ **销售订单带 `warehouse_id`**：采购订单不需要（入库时才知道进哪个仓），但发货必须知道**从哪个仓扣库存**，
>   否则出库那一刻还得再问一次人，超发拦截也无从谈起。
> ★ 明细累计列叫 `shipped_qty`（已发），对应采购的 `received_qty`（已收）；超发同样用条件更新拦截。
> ★ 退货单 `return_reason` 必填、`source_order_id` 可空（允许无单退货）。
> ★ 退货过账方向是 `IN`，但 `partner_id` 仍指向**客户**，因此 `post_bill_lines(partner_type="CUSTOMER")`
>   显式覆盖「按方向推导往来单位类型」的默认规则。

```sql
CREATE TABLE IF NOT EXISTS wms_sales_order (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    code               TEXT    NOT NULL UNIQUE,          -- SO + yyyymmdd + 4 位流水
    name               TEXT    NOT NULL,
    applicant_user_id  INTEGER NOT NULL REFERENCES users(id)      ON DELETE RESTRICT,
    customer_id        INTEGER          REFERENCES partners(id)   ON DELETE RESTRICT,  -- type='CUSTOMER'
    customer_name_snap TEXT,                             -- 快照：客户改名不影响历史单据
    warehouse_id       INTEGER NOT NULL REFERENCES warehouses(id) ON DELETE RESTRICT,  -- 出库仓库
    order_date         TEXT    NOT NULL,
    total_qty          INTEGER NOT NULL DEFAULT 0,
    total_amount       REAL    NOT NULL DEFAULT 0,
    status             TEXT    NOT NULL DEFAULT 'DRAFT'
                       CHECK (status IN ('DRAFT','SUBMITTED','APPROVED','REJECTED','CLOSED','CANCELED')),
    submit_at          TEXT,
    approve_at         TEXT,
    approver_id        INTEGER REFERENCES users(id) ON DELETE RESTRICT,
    reject_reason      TEXT,
    remark             TEXT,
    is_active          INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),  -- 0=作废（软删，永不物理删）
    created_at         TEXT    NOT NULL,
    updated_at         TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_wso_status   ON wms_sales_order(status, order_date DESC);
CREATE INDEX IF NOT EXISTS idx_wso_customer ON wms_sales_order(customer_id, order_date);

CREATE TABLE IF NOT EXISTS wms_sales_order_detail (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id           INTEGER NOT NULL REFERENCES wms_sales_order(id) ON DELETE CASCADE,
    product_id         INTEGER NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
    product_name_snap  TEXT    NOT NULL,
    barcode_snap       TEXT,
    unit_snap          TEXT    NOT NULL,
    price              REAL    NOT NULL DEFAULT 0 CHECK (price >= 0),
    qty                INTEGER NOT NULL CHECK (qty > 0),
    amount             REAL    NOT NULL DEFAULT 0,
    shipped_qty        INTEGER NOT NULL DEFAULT 0,       -- 累计发货（≤ qty，发货时条件更新回写）
    sort_order         INTEGER NOT NULL DEFAULT 0,
    remark             TEXT,
    created_at         TEXT    NOT NULL,
    updated_at         TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_wsod_order ON wms_sales_order_detail(order_id, sort_order);

CREATE TABLE IF NOT EXISTS wms_sales_return (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    code               TEXT    NOT NULL UNIQUE,          -- SR + yyyymmdd + 4 位流水
    name               TEXT    NOT NULL,
    source_order_id    INTEGER          REFERENCES wms_sales_order(id) ON DELETE RESTRICT,  -- 可空=无单退货
    order_code_snap    TEXT,
    customer_id        INTEGER NOT NULL REFERENCES partners(id)    ON DELETE RESTRICT,
    customer_name_snap TEXT,
    warehouse_id       INTEGER NOT NULL REFERENCES warehouses(id) ON DELETE RESTRICT,  -- 退回哪个仓库
    return_date        TEXT    NOT NULL,
    total_qty          INTEGER NOT NULL DEFAULT 0,
    total_amount       REAL    NOT NULL DEFAULT 0,
    status             TEXT    NOT NULL DEFAULT 'DRAFT'
                       CHECK (status IN ('DRAFT','SUBMITTED','APPROVED','REJECTED','CANCELED')),
    posted_at          TEXT,                             -- 过账时刻（写 IN 流水），非空=已入库
    posted_by          INTEGER REFERENCES users(id) ON DELETE RESTRICT,
    submit_at          TEXT,
    approve_at         TEXT,
    approver_id        INTEGER REFERENCES users(id) ON DELETE RESTRICT,
    reject_reason      TEXT,
    return_reason      TEXT    NOT NULL CHECK (length(return_reason) BETWEEN 1 AND 200),
    remark             TEXT,
    is_active          INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
    created_at         TEXT    NOT NULL,
    updated_at         TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_wsr_status   ON wms_sales_return(status, return_date DESC);
CREATE INDEX IF NOT EXISTS idx_wsr_customer ON wms_sales_return(customer_id, return_date);

CREATE TABLE IF NOT EXISTS wms_sales_return_detail (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    return_id          INTEGER NOT NULL REFERENCES wms_sales_return(id) ON DELETE CASCADE,
    order_detail_id    INTEGER          REFERENCES wms_sales_order_detail(id) ON DELETE SET NULL,
    product_id         INTEGER NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
    product_name_snap  TEXT    NOT NULL,
    barcode_snap       TEXT,
    unit_snap          TEXT    NOT NULL,
    qty                INTEGER NOT NULL CHECK (qty > 0),
    price              REAL    NOT NULL DEFAULT 0 CHECK (price >= 0),
    amount             REAL    NOT NULL DEFAULT 0,
    sort_order         INTEGER NOT NULL DEFAULT 0,
    remark             TEXT,
    created_at         TEXT    NOT NULL,
    updated_at         TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_wsrd_return ON wms_sales_return_detail(return_id, sort_order);
```

> 流水侧：发货写 `ref_type='SALES_OUT'`（OUT），退货过账写 `ref_type='SALES_RETURN'`（IN），
> `partner_id` 两者都指向客户 —— 客户对账单（`GET /api/wms/customer-statement`）只读这两类流水，
> 金额一律取账本 `amount`，**不取单据合计**，这样部分发货、红字冲销、退货都不会与库存对不上。

## 6. 迁移机制

```
desktop/db/migrations/
  0001_init.sql          基线（含全部建表 + 索引 + 种子）
  0002_wms_bills.sql     单据层地基：warehouses 升级两级树 + stock_logs 加 ref_type/ref_id
                         （依据 docs/13 第 4.1 / 4.5 节）
  0003_wms_purchase.sql  采购订单 + 采购入库单（P2/P3，见 docs/13 第 11 章）
  0004_wms_operation.sql 领用/退库/归还/借用/调拨单（P4）
  0005_wms_stocktake.sql 盘点单（P0-2，见 docs/14 第 4 章）
  0006_wms_sales.sql     销售订单 + 销售退货（P1-4，见 docs/14 第 6 章）
```

> ★ **迁移编号是全项目唯一的，合并前必须核对目标库**：`schema_meta` 的最大版本必须与
> `db/migrations/` 目录里的最大编号一一对应。若目标库里已有 `version=2` 而仓库里没有对应文件
> （来自其它分支、本地未提交的迁移、或曾用不同编号），新写的 `0002` 会被**静默跳过**，
> 而 `0003`/`0004` 会照常执行 → 库处于「半迁移」不一致状态（表建了、列没加，报 `no such column`）。
> 排查两条 SQL：`SELECT version, applied_at FROM schema_meta ORDER BY version;` 与
> `PRAGMA table_info(<表名>);`。补齐时按「列不存在才 ADD」幂等执行，不要直接改 `schema_meta`。
>
> ★ 0002 起**一律用 `ALTER TABLE ADD COLUMN` 加列，禁止「建新表-拷贝-改名」四步法**：
> 迁移器（`core/migrator.py`）开连接时 `PRAGMA foreign_keys = ON`，此时 `DROP TABLE warehouses`
> 会触发 `stock_current` 的 `ON DELETE CASCADE` —— 库存余额会被静默清空。
> `ADD COLUMN` 在 SQLite 全版本可用，且不动历史行，是本项目唯一允许的加列方式。

启动流程：读 `MAX(version) FROM schema_meta`（表不存在视为 0）→ 遍历 `migrations/*.sql` 中编号更大者 → 逐个「单事务执行 + 写入 `schema_meta`」→ 任一失败**整体回滚并终止启动**（不允许带病运行）。

规则清单：
1. 禁止修改已应用的迁移文件；写错了就加新文件向前修复。
2. 迁移文件内禁止 `DROP TABLE`/`DROP COLUMN` 不带备份动作（SQLite 的 DROP COLUMN 需 3.35+，且旧库可能更低版本 → 用「建新表-拷贝-改名-重建索引」四步，并在注释标注耗时）。
3. 每次迁移前**强制自动备份**（15.3 RPO 设计的一部分）。
4. `schema.sql`（全量基线，给新库）与 `migrations/`（给老库）必须同步维护；两者不一致时以 migrations 顺序执行结果为准，并把 `schema.sql` 改正过来。

## 7. 未来迁移路径（SQLite → PostgreSQL）

本项目所有 SQL 集中在 `desktop/models/*_repo.py`，这是唯一出口。若用户量超过 5 人或单据超 1000/天，SQLite 写串行会成瓶颈，迁移成本可控：

| 差异点 | 处置 |
|---|---|
| 自增 | `INTEGER AUTOINCREMENT` → `BIGSERIAL` |
| 时间 | `TEXT` → `TIMESTAMPTZ`（注意本项目语义是东八区本地时间，迁移需 `AT TIME ZONE`） |
| 布尔 | `INTEGER 0/1` → `BOOLEAN` |
| UPSERT | `INSERT OR IGNORE` → `INSERT ... ON CONFLICT DO NOTHING` |
| 参数占位 | `?` → `%s` |
| 连接 | 每请求一连接 → 连接池（`psycopg` pool），`pool_pre_ping` |
| 级联/外键 | 语法兼容，无差异 |

Repository 层已按「单文件单出口」组织，正是为此预留。**但 V1 严禁提前抽象出数据库方言层**——那是把简单项目复杂化的典型错误。
